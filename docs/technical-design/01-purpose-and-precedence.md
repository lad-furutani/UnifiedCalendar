# 1. 設計目的・前提と基準仕様書との関係

本書は、基準仕様書の第1～20章を初期版の外部仕様として維持したまま、第21章の未確定事項と、その後の会話で確定した技術判断を実装可能な形へ解決する内部設計書である。Codexは本書を構造・依存・実装順の根拠とし、画面文言・操作・機能範囲の判断では基準仕様書を参照する。

## 1.1 規範の優先順位

1.  この依頼に明記された確定技術判断。特にOAuthトークンのDPAPI保護は、基準仕様書の旧記述より新しい明示決定として扱う。

2.  基準仕様書 v1.0 の第1～20章。製品挙動、表示、操作、エラー時フォールバック、初期版対象外を規定する。

3.  本書の推奨実装詳細。上位2つと矛盾しない範囲でCodexが従う。

> **変更禁止**  検索、編集、通知、印刷、エクスポート、Push/Webhook、自動更新、重複統合、右端自動ドッキング等を、実装上便利という理由で追加しない。

## 1.2 設計対象と非対象

- 対象はWindows 11 x64の単一ユーザー向け常駐WPFアプリ。複数Google/Microsoftアカウントと選択カレンダーを参照専用で統合する。

- 外部同期と1分内部更新を分離し、オフライン時は最後の正常キャッシュを表示する。

- APIやUIのSDK型はProvider内へ閉じ込め、CoreとUIは共通モデルだけを扱う。

- バックエンド、クラウド中継、サーバーDB、ユーザー間共有、テレメトリ基盤は設計対象外。

## 1.3 設計上の用語

| 用語 | 意味 |
| --- | --- |
| 外部同期 | Google Calendar API / Microsoft Graphから予定を再取得する処理。初期5分、設定候補1/5/10/15/30/60分。 |
| 内部更新 | 外部APIへ触れず、現在時刻、終了判定、進捗、日付グループを1分ごとに再評価する処理。 |
| 表示対象アカウント | 有効で、表示ONかつ取得可能なカレンダーを1件以上持つアカウント。 |
| スナップショット | Provider結果またはキャッシュを共通モデルへ正規化した読み取り専用の一貫した集合。 |
| 安定ID | サービス、内部アカウントID、カレンダーID、元イベントID、繰り返し回識別情報から作る複合キー。 |
