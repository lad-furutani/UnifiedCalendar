# 1 目的・前提

**GEN-001  目的：**利用者がWindowsデスクトップ上で、Google CalendarとMicrosoft 365の今後の予定を素早く参照できることを目的とする。

**GEN-002  利用形態：**個人利用を前提とする常駐型Windowsアプリとする。画面右端に縦長で置く使い方を想定するが、右端配置は利用例でありアプリが強制しない。

**GEN-003  参照専用：**予定の閲覧に特化し、アプリ内で予定の新規作成、編集、削除を行わない。必要な変更は元サービスで行う。

**GEN-004  統合表示：**Google CalendarとMicrosoft 365の予定を、取得元を識別できる単一一覧へ統合する。取得元は並び順の優先条件にしない。

**GEN-005  複数登録：**Google、Microsoftとも複数アカウントを登録でき、各アカウント内の複数カレンダーを個別に表示ON/OFFできる。

**GEN-006  対象期間：**今日を起点として設定日数分を対象とする。初期値は7日、設定可能範囲は1～90日、表示件数上限は設けない。

**GEN-007  時刻基準：**一覧・詳細・終了判定はWindowsの現在のローカルタイムゾーンを基準とし、OSのタイムゾーン変更に追従する。

**GEN-008  データと表示の分離：**サービス固有イベントを共通予定モデルへ変換し、その後にフィルタ、ソート、色決定、UI表示を行う構成を前提とする。

**GEN-009  日本語表示：**確定した日付・状態文言は日本語とし、時刻は24時間表記、曜日付き日付を用いる。製品全体の対応言語範囲は未確定事項に残す。

**GEN-010  権威ある仕様：**本書内で『確定』とした要件を初期版の外部仕様とする。具体的な数値・API・技術方式が未決定のものだけを第21章に集約する。

# 2 機能仕様

**FUN-001  予定取得：**有効なアカウントの表示ONカレンダーから、対象期間内の予定を取得する。表示OFFカレンダーは予定取得・表示・キャッシュ対象外とする。

**FUN-002  統合一覧：**取得した予定を日付ごとにグループ化し、終日予定を先頭、時刻指定予定を開始時刻昇順で表示する。

**FUN-003  経時更新：**現在時刻表示、進行中判定、背景進捗、終了済み予定の除外を1分ごとに再評価する。この内部更新では外部APIへアクセスしない。

**FUN-004  詳細参照：**予定行のシングルクリックまたはキーボード操作により詳細ポップアップを表示し、元サービスの詳細ページや会議URLを既定ブラウザで開ける。

**FUN-005  色分け：**元サービスの予定色・カテゴリ色を利用し、ユーザー定義ルールが一致した場合は独自色で上書きする。

**FUN-006  オフライン表示：**起動時または同期失敗時に、最後に正常取得したローカルキャッシュを利用して予定と詳細を表示する。

**FUN-007  手動更新：**メイン画面とタスクトレイメニューから、有効かつ表示対象を持つ全アカウントの即時同期を開始できる。

**FUN-008  アカウント運用：**アカウント追加、再認証、有効/無効切替、削除、カレンダー選択、同期状態確認を設定画面で行える。

**FUN-009  検索・編集の非提供：**検索、絞り込み、予定編集、印刷、エクスポートは提供しない。単純な時系列参照を優先する。

**FUN-010  開始前通知（1.1.0で追加）：**時刻が設定されている予定について、開始の指定分前にWindowsの通知を出す。ON/OFFと分数を設定でき、アカウント別・カレンダー別の設定は持たない。詳細は13.3とする。

# 3 画面仕様

## 3.1 メイン画面

**UI-001  構成：**固定ステータス領域、その下のスクロール可能な日付別予定一覧で構成する。日付Sticky Headerはステータス領域の直下で動作する。

**UI-002  ステータス順：**左から『現在時刻』『最終正常更新時刻』『同期状態』『手動更新ボタン』『設定ボタン』の順で固定する。設定ボタン（1.1.0で追加）は歯車アイコンとし、押すと設定画面を開く。タスクトレイメニューの『設定』と同じ動作とし、どちらの導線も残す。**『同期状態』『手動更新ボタン』『設定ボタン』の3つのボタンは同じ高さで揃える（1.2.0で変更。1.1.0までは手動更新ボタンだけが文字に合わせた自動サイズで、他の2つより高かった）。**

**UI-003  現在時刻：**『12:36』のように24時間・分単位で表示し、日付と秒は表示しない。1分ごとに更新する。

**UI-004  最終更新表示：**正常更新日が今日なら『最終更新 12:35』、今日以外なら『最終更新 8/27 12:35』と表示する。同期エラー中も直近の正常値を保持する。ウィンドウ幅が不足する場合は末尾を省略記号で切る（1.1.0で追加）。現在時刻、同期状態、手動更新ボタン、設定ボタンは切らない。

**UI-005  正常状態：**全対象が正常な場合は同期状態の文字や正常アイコンを表示しない。問題がある場合だけ対象アカウントが分かる状態表示を出す。

**UI-006  エラー状態：**ステータス領域に同期エラーを視覚的に強調し、長い場合は1行の末尾を省略記号で切り、ホバーで全文を表示する。モーダルダイアログは出さない。

**UI-007  更新表示：**手動・自動を問わず同期中は更新ボタンをスピナーへ切り替え、必要に応じて『更新中』ツールチップを出す。画面全体はブロックしない。

**UI-008  空状態：**対象期間内に予定がない場合は『今後N日間の予定はありません』と表示する。Nは表示日数設定に連動する。

**UI-009  未登録状態：**アカウントが0件なら『アカウントを追加してください』とGoogleアカウント追加、Microsoftアカウント追加の2ボタンを表示する。自動的に設定画面は開かない。

**UI-010  初回取得中：**キャッシュがない状態で最新予定を取得中の場合は『予定を取得中…』と表示する。取得成功後に通常一覧へ移行し、失敗時は同期エラーを表示する。

**UI-011  テーマ：**タイトルバー、設定画面、ステータス、一覧周辺UIはWindowsのライト/ダークテーマに追従し、実行中のテーマ変更も即時反映する。予定固有の背景色は維持する。

**UI-012  タイトルバー：**アプリ名のみを表示する。現在時刻や同期状態を重複表示しない。

## 3.2 設定画面

**UI-013  カテゴリ：**『アカウント』『カレンダー選択』『表示』『色分けルール』『更新』『通知』『一般』の7カテゴリで構成する。『通知』は1.1.0で追加した。

**UI-014  モード：**モードレス画面とし、開いたままメイン画面を操作できる。同時表示は1つだけとし、再度開く操作では既存画面を前面に出す。

**UI-015  位置・サイズ：**設定画面の位置・サイズを保存して次回復元し、画面外・モニタ・DPI変更時は操作可能な位置へ補正する。**保存する矩形の決め方はメインウィンドウと同じとする（1.2.0で変更。WIN-001a / TBD-021）。スナップした大きさは保存し、最大化した状態は保存しない。**

**UI-016  確定操作：**OK、キャンセル、適用を用意する。OKは未適用変更を反映して閉じ、適用は反映して残り、キャンセルは未適用変更だけを破棄する。

**UI-017  閉じる操作：**右上の×は未適用変更がなければ閉じ、ある場合は破棄確認を表示する。即時反映済みの変更はキャンセルや×で元に戻さない。

**UI-018  終了時：**設定画面を開いたままアプリ終了する場合、未適用変更があれば適用または破棄を確認する。

# 4 予定一覧表示仕様

## 4.1 対象・日付グループ

**LST-001  日付範囲：**今日を含むN日間を表示する。通常の過去日は対象外だが、過去日に開始して現在も進行中の時刻指定予定は例外として表示する。

**LST-002  日付ヘッダー：**今日を『今日 8/27(木)』、明日を『明日 8/28(金)』、それ以降を『8/29(土)』と表示する。今日・明日にも実日付を必ず併記する。

**LST-003  相対表現：**『明後日』『○日後』は用いない。祝日名は表示せず、外部から祝日情報も取得しない。

**LST-004  予定のない日：**予定がある日だけ日付ヘッダーを表示する。今日の予定が全て終了したら今日ヘッダーも消し、次に予定がある日から始める。

**LST-005  Sticky Header：**スクロール中の日付ヘッダーを一覧上部へ固定し、次の日付グループへ到達したら表示日付を切り替える。

## 4.2 並び順

**LST-006  最終表示順：**日付昇順でグループ化し、各日では終日予定を先頭、その後に時刻指定予定を開始時刻昇順で並べる。同一開始時刻は件名昇順とする。

**LST-007  取得元非優先：**Google/Microsoft、アカウント、カレンダーはソート優先条件にしない。内部アルゴリズムは任意だが、最終結果順を保証する。

**LST-008  進行中の位置：**進行中予定を先頭へ繰り上げず、既定の時刻順を維持する。進行中は見た目だけで表現する。

**LST-009  重複：**両サービスに同内容の予定が存在しても自動統合せず、独立した予定として表示する。

## 4.3 予定種別と終了判定

**LST-010  時刻指定予定：**開始後も終了時刻までは表示し、終了時刻に達した予定は1分ごとの内部更新で一覧から除外する。終了後の残留、フェード、履歴表示は行わない。

**LST-011  進行中表示：**開始～終了に対する現在時刻の割合を算出し、行背景を左から右へ進む時間進捗として表示する。経過済み領域と未経過領域は同じ基準色の濃淡で区別し、1分ごとに更新する。

**LST-012  進行中ラベル：**『進行中』文字、専用アイコン、現在時刻ラインは表示しない。背景進捗だけで状態を表す。

**LST-013  単日終日：**『終日  件名』と表示し、対象日の翌日0:00で非表示にする。時間進捗は適用しない。

**LST-014  複数日終日：**期間中は常に1件だけ表示し、日ごとに重複させない。『終日  8/27～8/29  件名』のように期間を示し、最終日の翌日0:00で非表示にする。

**LST-015  複数日時刻指定：**開始日のグループに1件だけ表示し、終了日側へ重複表示しない。開始日が過去で現在も進行中なら、今日のグループへ移して表示し、終了後に消す。

**LST-016  日付またぎ時刻：**一覧では『23:00–01:00』のように時刻だけ表示し、詳細で開始・終了双方の日付を示す。

**LST-017  同一開始終了：**開始時刻と終了時刻が同一なら一覧は開始時刻だけ表示する。詳細では取得元の開始日時・終了日時を表示する。ライフサイクル判定は未確定事項とする。

**LST-018  繰り返し予定：**各回を通常予定として個別表示し、例外変更は変更後内容、特定回キャンセルはその回だけ非表示とする。

**LST-019  キャンセル予定：**取得元でキャンセル済みの予定は一覧・詳細・キャッシュ表示対象から除外する。

**LST-020  辞退予定：**辞退済みも表示する。承諾済みは通常表示、辞退・未回答・仮承諾など注意が必要な状態だけ一覧上で識別可能にする。

## 4.4 行レイアウトと操作

**LST-021  1行1件：**予定は折り返さず常に1行で表示する。左から『時刻』『件名』『参加状態』『会議参加アイコン』『取得元サービス記号』の順に固定する。

**LST-022  時刻欄：**現在のフォントサイズ、DPI、表示形式から幅を自動算出し、一覧の全行で揃える。『10:00–11:00』『終日』等が収まる幅を基準とする。

**LST-023  長い件名：**表示幅を超える件名は末尾を省略記号で切る。横スクロールや2行表示は行わない。

**LST-024  ツールチップ：**Windows標準の待ち時間で、件名全文と開始～終了時刻を表示する。終日は『終日』、複数日は必要な日付を含め、注意が必要な参加状態だけ追記する。

**LST-025  取得元記号：**公式ロゴは使わず、一覧ではG/M等の独自記号を用いる。サービス固定色は持たず、背景とのコントラストに応じて色を自動補正する。

**LST-026  会議アイコン：**会議URLを持つ予定だけ表示し、クリックまたはキーボード操作で既定ブラウザを開く。背景に応じて色を自動補正する。

**LST-027  クリック：**行のシングルクリックで詳細ポップアップ、ダブルクリックで元サービスの予定詳細ページを開く。右クリックメニューは表示しない。

**LST-028  会議クリック分離：**会議アイコンのクリックは会議URLを開く処理だけを行い、行のシングルクリックとして扱わず詳細ポップアップを開かない。

**LST-029  ホバー：**背景または枠を控えめに変化させ、クリック可能であることを示す。元の色と時間進捗を判別できる強さに留め、件名へ下線は付けない。

**LST-030  フォーカス：**キーボードフォーカス中は枠線等で位置を明示し、予定背景色と進捗表示は維持する。

**LST-031  区切り：**予定行間に約1pxの控えめな区切り線を表示する。日付ヘッダーと予定行の境界は予定行間より少し明確にする。角丸は使わない。

**LST-032  密度連動：**行高さ、上下左右余白、アイコン配置はコンパクト/標準/ゆったり、フォントサイズ、DPIに応じて再計算する。

**LST-033  スクロール：**内容が表示領域を超えた場合だけ縦スクロールバーを表示し、マウスホイールとタッチパッドに対応する。

**LST-034  更新時の位置：**1分更新・同期・追加削除でも可能な限り閲覧位置を維持する。対象行が消えた場合は元位置に最も近い位置へ補正し、先頭や現在時刻へ強制移動しない。

**LST-035  新規・変更強調：**新規予定、前回から変更された予定にNEW、一時ハイライト、変更マーカー、更新履歴を表示しない。常に最新内容だけを表示する。

**LST-036  非対応操作：**一覧上の件名は選択・コピー不可とし、Space、右クリック、行ドラッグ、手動並び替え、外部アプリへのドラッグ&ドロップには動作を割り当てない。

# 5 詳細ポップアップ仕様

**POP-001  起動：**予定行のシングルクリックまたはフォーカス中のEnterで、一覧レイアウトを崩さないポップアップとして表示する。

**POP-002  同時数：**常に1つだけ表示する。別予定を選ぶと既存ポップアップの内容を切り替える。

**POP-003  配置：**対象予定行付近を基準に、画面外へはみ出さないよう上下左右を自動調整し、現在のモニタ内へ収める。

**POP-004  サイズ：**内容量に応じて可変とし、最大サイズを設ける。超過内容はポップアップ内部でスクロールし、ユーザーによる自由リサイズは提供しない。

**POP-005  項目順：**件名、日時、場所、オンライン会議URL、説明、取得元、カレンダー名の順とする。値が空の項目はラベルごと非表示にし、『なし』『未設定』は表示しない。

**POP-006  参加状態：**承諾、仮承諾、未回答、辞退など取得できる本人の参加状態を明示する。表示位置の具体値は未確定事項とする。

**POP-007  日時表記：**通常は『8/27(木) 10:00 ～ 11:00』、日付またぎは『8/27(木) 23:00 ～ 8/28(金) 1:00』とし、通常は年を表示しない。

**POP-008  終日日時：**単日は『8/27(木) 終日』、複数日は『8/27(木) ～ 8/29(土) 終日』とし、API内部の排他的終了境界はユーザー向け表示へ変換する。

**POP-009  説明：**HTML・リッチテキストをプレーンテキストへ変換し、タグや装飾を除去する。説明は最初から全文を表示し、最大サイズ超過時は内部スクロールする。

**POP-010  URL：**会議URL、場所、説明に含まれるURLを検出し、URL部分だけクリック可能にする。クリックは既定ブラウザで開く。

**POP-011  会議URL表現：**サービス名や『会議に参加』へ置換せず、URL文字列をそのまま表示する。

**POP-012  取得元表示：**取得元サービス名とカレンダー名を文字列として下部の補足情報エリアにまとめる。サービス名の横に装飾アイコンは付けない。

**POP-013  元予定を開く：**補足情報エリア付近に、元サービスの予定詳細ページを開くための独立した操作アイコン/ボタンを置く。クリックまたはEnterで既定ブラウザを開く。

**POP-014  コピー：**件名、場所、説明、URL等をWindows標準操作で選択し、Ctrl+Cでコピーできる。専用の『すべてコピー』ボタンは設けない。

**POP-015  閉じる：**Esc、ポップアップ外クリック、一覧スクロール開始で閉じる。リンクや元予定ページを開いたときは閉じない。

**POP-016  ウィンドウ変化：**メインウィンドウの移動・リサイズ開始、最小化、タスクトレイ格納、DPI変更、モニタ移動で閉じ、自動復元しない。

**POP-017  データ更新：**同一予定IDが同期で更新された場合は表示内容を即時更新する。対象予定が削除・終了・非表示化された場合はポップアップを閉じる。

**POP-018  Esc優先：**テキスト選択中やリンクにフォーカス中でも、Escは常にポップアップを閉じる。ポップアップがないときのEscには動作を割り当てない。

# 6 Google Calendar / Microsoft 365連携仕様

**INT-001  対象サービス：**Google Calendar APIとMicrosoft Graphのカレンダー機能を利用する。具体的なAPIバージョン、エンドポイント、SDKは技術設計で決定する。

**INT-002  OAuth：**Google/MicrosoftのOAuthを使用し、サービスのアカウントパスワードは保存しない。認証完了後は再起動後も利用できる認証情報を保持する。

**INT-003  読み取り専用権限：**初期版は予定参照だけを行い、予定作成・編集・削除権限を要求しない。実際の最小スコープは技術設計で確定する。

**INT-004  共通モデル：**サービス固有データを共通予定モデルへ正規化する。サービス差異をUIへ直接露出させず、取得元情報は識別用に保持する。

**INT-005  ページング：**API結果が複数ページの場合、対象期間内の予定を全て取得するまで内部でページングを継続する。件数で打ち切らない。

**INT-006  繰り返し展開：**対象期間の繰り返し予定を各回へ展開し、例外変更・キャンセルを反映する。安定IDの組み立て方法は未確定事項とする。

**INT-007  取得元詳細：**各予定について元サービス側の詳細ページを開く識別情報またはURLを保持する。

**INT-008  会議URL：**Teams、Google Meet、Zoom等、URLで開けるオンライン会議情報を共通meetingUrlへ正規化する。

**INT-009  色：**取得元の予定色・カテゴリ色を共通色表現へ変換する。カレンダー色はカレンダー選択画面とオフライン復元用メタデータとして保持する。

**INT-010  変更通知：**Google Push Notification、Microsoft Graph Change Notification、Webhookを初期版では利用しない。更新はポーリングと手動更新で行う。

**INT-011  レート制限：**Retry-After等のサービス指示が得られる場合はそれに従い、連続リトライを避ける。待機中は既存キャッシュを維持する。

**INT-012  Microsoft共有カレンダー：**初期版は、認証ユーザー自身のOutlook予定表一覧へ追加済みで、Microsoft Graphのユーザー自身のコンテキストから列挙できる共有カレンダーを予定取得・表示対象とする。共有元メールボックスの直接参照や、Outlook予定表一覧へ未追加の共有・委任カレンダーの直接探索は対象外とする。

# 7 アカウント・カレンダー管理仕様

## 7.1 アカウント

**ACM-001  複数アカウント：**Google/Microsoftの両方で複数アカウントを登録できる。同一サービス・同一アカウントの重複登録は不可とし、サービスが異なれば同一メールでも別アカウントとする。

**ACM-002  一覧項目：**取得元サービス、表示名またはメールアドレス、有効/無効、同期状態、最終正常更新時刻、認証エラー状態を表示する。

**ACM-003  並び順：**Google、Microsoftの順でサービス別にグループ化し、各サービス内はアカウント名/メールアドレス昇順とする。手動並び替えは設けない。

**ACM-004  追加ボタン：**『Googleアカウントを追加』『Microsoftアカウントを追加』を個別に表示し、押下後に対応サービスのOAuthフローを開始する。

**ACM-005  追加後フロー：**認証完了後、そのアカウントの取得可能カレンダー一覧を続けて表示し、表示ON/OFFを設定してからアカウント一覧へ戻る。

**ACM-006  初回同期状態：**アカウント追加後は初回同期完了まで『同期中』とし、成功で通常状態、失敗でそのアカウントだけ同期エラーへ移行する。設定画面は待たずに閉じられる。

**ACM-007  一覧操作：**再認証、有効/無効切替、削除をアカウント一覧から直接操作できる。削除は確認ダイアログを必須とする。

**ACM-008  無効化：**無効化した時点で当該アカウントの予定を即時非表示にし、自動・手動同期対象から外す。設定と認証情報は保持し、再有効化時は即時同期する。

**ACM-009  削除：**確認後、認証情報、アカウント設定、カレンダー選択、専用キャッシュ、その他ローカル関連情報を全て削除し、他アカウントへ影響させない。

**ACM-010  再認証：**設定画面またはメイン画面のエラー導線から開始できる。成功後はそのアカウントだけ即時同期し、正常化すれば警告を解除する。

## 7.2 カレンダー

**ACM-011  一覧項目：**カレンダー名、所属アカウント、取得元サービス、元サービスのカレンダー色、表示ON/OFFを表示する。

**ACM-012  長い名称：**カレンダー名は1行で末尾を省略し、ホバーで全文を表示する。折り返し・横スクロールは行わない。

**ACM-013  初期選択：**新規アカウントはメインカレンダーだけをON、他をOFFとする。サービス側の表示設定は引き継がない。

**ACM-014  メインカレンダー：**他のカレンダーと同様に個別ON/OFFでき、OFF時に警告を出さない。

**ACM-015  一括操作：**『すべてON/すべてOFF』およびアカウント単位の一括切替を設けず、カレンダーごとに操作する。

**ACM-016  取得不可：**権限不足等のカレンダーも一覧に表示するがONにはできず、『権限不足』『予定取得不可』等の理由を示す。通常の同期エラーとは区別する。

**ACM-017  一覧再取得：**カレンダー選択画面を開いた時点で再取得する。予定同期は、表示中のカレンダー一覧を書き換えない。失敗時は前回一覧とON/OFFを維持して失敗を表示する。

**ACM-018  OFF反映：**OFFにした時点で当該カレンダーの予定を即時非表示にし、同期・キャッシュ対象から外す。登録情報は保持する。

**ACM-019  ON反映：**ONに戻した時点で当該カレンダーを即時同期し、成功後に一覧とキャッシュへ反映する。失敗時は当該カレンダー/アカウントのエラーとする。

**ACM-020  全OFFアカウント：**アカウント自体は有効のまま保持するが、予定同期対象から外し、予定とメイン警告を表示しない。設定画面では認証状態を確認でき、最終正常更新時刻は保持する。

**ACM-021  Microsoft共有カレンダーの追加前提：**目的の共有カレンダーがカレンダー選択一覧へ現れない場合は、先にOutlook側で共有を受諾して予定表一覧へ追加し、その後に本アプリでカレンダー一覧を再取得するよう案内する。

# 8 同期・更新仕様

**SYN-001  外部同期周期：**Google/Microsoftからの自動再取得は初期値5分とし、1/5/10/15/30/60分の固定候補から選択する。

**SYN-002  内部更新周期：**現在時刻、時間進捗、終了済み除外を1分ごとに更新し、外部再取得とは分離する。

**SYN-003  起動時：**キャッシュを即時表示した後にバックグラウンドで最新同期する。キャッシュがなければ取得中表示を出す。

**SYN-004  スリープ復帰：**スリープ/休止復帰を検出したら通常周期を待たず即時同期し、進行中・終了済みも再評価する。

**SYN-005  ネットワーク復帰：**接続イベントは監視しない。復帰後は次回定期同期またはユーザーの手動更新で再取得する。

**SYN-006  起動時オフライン：**キャッシュを表示して短い間隔で数回だけ再試行し、それでも失敗したら通常周期へ戻る。該当アカウントは同期エラーとする。

**SYN-007  手動更新：**メイン画面更新ボタンとタスクトレイ『今すぐ更新』から、有効かつ表示ONカレンダーを持つ全アカウントを更新する。

**SYN-008  UI非ブロック：**同期中も一覧スクロール、詳細表示、会議URL、元予定ページ、設定、終了等を利用できる。現在表示中のデータを保持する。

**SYN-009  更新中ボタン：**同期中は手動更新ボタンを無効化し、追加の手動要求を開始できない。終了後に通常アイコンへ戻す。

**SYN-010  重複要求：**同一アカウントで同期中に自動周期・復帰等の別要求が重なった場合は並列実行せず、再更新要否を記録し、完了後に最大1回へ集約する。

**SYN-011  アカウント並列：**複数アカウントはアカウント単位で並列同期し、内部同時実行上限を設け、超過分を待機キューへ入れる。上限はユーザー設定にしない。

**SYN-012  アカウント内取得：**同一アカウント内の複数カレンダーを並列/順次のどちらで取得するかは各API特性を踏まえた実装設計に委ねる。

**SYN-013  順次反映：**完了したアカウントから一覧へ反映し、全アカウント完了を待たない。遅延・失敗アカウントが正常側の反映を妨げない。

**SYN-014  アカウント部分成功：**成功アカウントは最新データへ更新し、失敗アカウントは前回キャッシュを維持する。全体ロールバックは行わない。

**SYN-015  カレンダー部分成功：**同一アカウント内でも成功カレンダーは更新し、失敗カレンダーは前回キャッシュを維持する。アカウント全体を前回状態へ戻さない。

**SYN-016  タイムアウト：**API通信に固定タイムアウトを設ける。タイムアウト時は該当アカウント/カレンダーの失敗としてキャッシュを維持する。具体値はユーザー設定にしない。

**SYN-017  一時エラー再試行：**通信失敗や一時APIエラーは短い間隔で固定回数だけ自動再試行し、無限リトライしない。具体値は実装設計で決定する。

**SYN-018  レート制限再試行：**一般リトライと分け、サービスの再試行指示へ従う。待機状態を必要に応じてアカウント状態へ表示する。

**SYN-019  削除反映：**元サービスで削除された予定は次回正常同期で一覧とキャッシュから除外する。同期失敗中は前回キャッシュに一時的に残り得る。

**SYN-020  表示差分：**更新時に一覧全体を空にせず、ちらつきや一瞬の空表示を見せない。差分更新等の内部方式は自由とする。

**SYN-021  状態維持：**可能な限りスクロール、選択、同一予定IDのキーボードフォーカスを維持する。フォーカス行が削除された場合は同位置の次行、なければ前行、一覧が空なら解除する。

**SYN-022  初回同期後スクロール：**起動時はキャッシュの直近予定を表示し、初回同期完了までユーザーがスクロールしていなければ最新データの直近予定へ合わせる。操作済みなら維持する。

**SYN-023  通常更新後スクロール：**定期同期・内部更新では直近予定へ強制移動しない。

**SYN-024  更新間隔変更：**同期中に自動更新間隔を変更しても進行中処理へ影響させず、完了後の次回スケジュールから新設定を使う。

# 9 キャッシュ仕様

**CAC-001  目的：**起動直後と通信/API障害時のフォールバック表示に利用し、一覧と詳細をオフラインでも復元できるようにする。

**CAC-002  世代：**最新1回分だけを保持し、履歴世代管理は行わない。

**CAC-003  単位：**アカウントごとに別ファイルとし、一部アカウントの失敗が他のキャッシュ更新へ影響しないようにする。命名規則は実装設計で決める。

**CAC-004  形式：**人が読めるJSON系テキスト形式とし、スキーマバージョンを持たせる。

**CAC-005  対象カレンダー：**表示ONカレンダーの予定だけを保存し、OFF予定を保存しない。OFF時は次回キャッシュ更新で除外し、ON時は即時同期後に保存する。

**CAC-006  予定項目：**件名、開始/終了、終日/複数日、場所、説明、会議URL、取得元、アカウント/カレンダー識別、カレンダー名、参加状態、色、元予定ページ情報、同期に必要な安定IDを保持する。

**CAC-007  カレンダーメタデータ：**カレンダーID、カレンダー名、カレンダー色を保存し、オフライン時に表示を復元する。ON/OFFは設定ファイル側で管理する。

**CAC-008  保存タイミング：**同期で新しい正常データが確定した時点で保存する。アプリ終了時に改めて保存・再同期せず、進行中同期の中途半端な結果は反映しない。

**CAC-009  部分成功保存：**成功カレンダーの最新データと失敗カレンダーの前回データをマージした一貫したスナップショットとして保存する。全対象失敗時は既存ファイルを変更しない。

**CAC-010  原子的書込み：**一時ファイルへ書き込み・フラッシュ後、既存ファイルと置換する。直接上書きしない。

**CAC-011  破損：**読み込めない場合は破損キャッシュを破棄し、空状態で起動して最新予定を再取得する。アプリを終了せずログへ記録する。

**CAC-012  暗号化：**初期版では暗号化せず、件名、説明、場所、URL等を通常のJSONとして保存する。保存先アクセス権で保護し、将来の安全な保存方式を拡張候補とする。

**CAC-013  削除連動：**アカウント削除時に当該アカウント専用キャッシュを削除する。

# 10 設定仕様

## 10.1 保存と反映

**SET-001  保存先：**ユーザーごとに%APPDATA%または%LOCALAPPDATA%配下へ保存する。実際の選択は技術設計で決定する。

**SET-002  形式：**人が読めるJSON系テキスト形式とし、スキーマバージョンを持つ。外部エディタで確認できる。

**SET-003  認証情報：**OAuthトークン等を初期版では同じローカル設定領域へ暗号化せず保存する。アカウントパスワードは保存しない。

**SET-004  保存タイミング：**アカウント、表示、色分け、更新等の主要変更は確定時に即時保存し、ウィンドウ状態は実行中に更新しつつ終了時にも保存する。

**SET-005  原子的書込み：**キャッシュと同様に一時ファイルへ書き込み後に置換し、直接上書きしない。

**SET-006  破損：**破損設定を別名退避し、初期設定で起動を継続してログへ記録する。退避命名・世代数は実装設計で決める。

**SET-007  外部編集：**起動中のファイル監視・自動再読込・再読込ボタンは設けず、次回起動時に反映する。

**SET-008  ファイルアクセス：**一般カテゴリから保存先フォルダと設定ファイル自体を開ける。アプリ内テキスト編集機能は提供しない。

**SET-009  反映区分：**表示日数、フォント、密度、色、カレンダーON/OFF等の軽量項目は即時反映を基本とし、アカウント追加・削除・再認証等は明示操作後に反映する。未反映状態をUIで識別可能にする。

## 10.2 設定項目

**SET-010  表示：**表示日数、フォントサイズ、表示密度、共通デフォルト予定色を提供する。テーマ選択は設けない。

**SET-011  表示日数：**1～90日のスピンボックス、初期値7日。範囲外は入力・確定不可とし、変更を取得範囲・表示・空状態文言へ即時反映する。

**SET-012  フォントサイズ：**スピンボックスで設定し、予定行、日付ヘッダー、ステータス、詳細ポップアップへ連動する。最小/最大値はレイアウト検証で決める。フォント種類は固定する。

**SET-013  表示密度：**コンパクト/標準/ゆったりをラジオボタンで同時表示し、初期値は標準、変更は即時反映する。

**SET-014  共通色：**固定パレットとカラーピッカーの両方を提供し、変更は即時反映、文字色・進捗色は自動補正する。

**SET-015  更新：**自動更新間隔だけをユーザー設定とする。最終更新表示、手動更新、復帰時同期は固定動作であり設定項目にしない。

**SET-016  一般：**Windows起動時の自動起動だけを一般設定項目とし、初期値ONとする。アプリ情報、ログ保存先、設定保存先は補助操作として配置する。

**SET-017  アプリ情報：**アプリ名、バージョン、ビルド日時を表示する。初期版ではライセンス・著作権表示を必須としない。

**SET-018  ログアクセス：**ログ保存先フォルダと最新ログファイルを直接開く操作を提供する。ログ編集機能は持たない。

**SET-019  初期設定へ戻す：**確認後、表示日数、フォントサイズ、表示密度、共通色、自動更新間隔、自動起動、通知設定（1.1.0で追加）、色分けルールを即時初期化する。ルールは全削除する。

**SET-020  初期化除外：**アカウント、認証情報、カレンダーON/OFF、メイン/設定ウィンドウの位置・サイズは維持する。

**SET-021  通知（1.1.0で追加）：**予定開始前の通知のON/OFFを設定できる。初期値はONとする。アカウント別・カレンダー別の設定は持たない。

**SET-022  通知タイミング（1.1.0で追加）：**開始の何分前に通知するかを1～60分のスピンボックスで設定する。初期値は5分。範囲外は入力・確定不可とし、変更は即時反映する。通知OFFのときはスピンボックスを無効にする。

# 11 色分けルール仕様

## 11.1 色決定

**CLR-001  優先順位：**有効な独自ルールの上から最初に一致した色、元サービスの予定色/カテゴリ色、共通デフォルト色の順で決定する。

**CLR-002  表示方式：**予定行全体の背景色として適用する。左端バーや件名文字色だけの色分けへ切り替える設定は設けない。

**CLR-003  可読性：**背景明度に応じて文字、G/M記号、会議アイコンを白/黒等へ自動補正し、時間進捗の経過/未経過も識別できる濃淡へ補正する。

**CLR-004  共通デフォルト：**独自ルール不一致かつ元サービスの予定色/カテゴリ色がない予定だけへ適用する。既に別の色決定根拠がある予定は共通色変更の影響を受けない。

## 11.2 ルール定義

**CLR-005  ルール名：**必須、最大64文字、重複不可。大文字/小文字だけ異なる名前も重複とし、未入力・重複時は保存不可とする。

**CLR-006  条件数：**最低1条件を必須とし、上限は設けない。条件なしの常時一致ルールは許可しない。

**CLR-007  条件種別：**件名、カレンダー名、取得元サービスを提供する。場所、説明、参加状態、正規表現は初期版の条件にしない。

**CLR-008  条件リスト：**1ルールに縦並びの複数条件を追加・削除でき、同じ条件種別も複数追加できる。条件順は評価に影響せず、追加順のままで並べ替え不可とする。

**CLR-009  AND/OR：**ルール単位でANDまたはORを選ぶ。ANDは全条件一致、ORはいずれか1条件以上一致で適用する。

**CLR-010  件名/カレンダー比較：**部分一致または完全一致を選択し、大文字/小文字を区別しない。前後空白を除去して比較するが、内部空白・連続空白は正規化しない。

**CLR-011  文字正規化：**全角/半角、ひらがな/カタカナを同一視せず、入力文字列どおり比較する。

**CLR-012  空値：**比較値は必須で、前後空白除去後に空になる値も保存不可とする。

**CLR-013  カレンダー名入力：**現在取得できるカレンダー名候補から選択でき、自由入力も許可する。候補にない名前も保存できる。

**CLR-014  サービス条件：**GoogleまたはMicrosoftの単一選択とする。複数サービスは同一条件種別を複数追加しOR等で表現する。

**CLR-015  色入力：**固定パレットと任意色カラーピッカーの両方を提供する。

**CLR-016  プレビュー：**固定サンプル予定行で背景色、自動文字色、進行中の進捗色を即時プレビューする。実予定データは使わない。

## 11.3 ルール管理

**CLR-017  一覧項目：**有効/無効、ルール名、条件概要、設定色を表示する。AND/ORは独立列にせず条件概要へ含める。

**CLR-018  条件概要：**『件名に「定例」を含む AND 取得元=Microsoft』等の簡潔な要約を表示し、幅超過は省略、ホバーで全文を表示する。

**CLR-019  優先順位編集：**ドラッグ&ドロップと上へ/下へボタンの両方で並び替え、上から順に評価して最初の一致を採用する。

**CLR-020  操作：**追加、編集、削除をアイコンボタン中心で提供し、ツールチップと必要なラベルを併用する。ダブルクリックでも編集画面を開ける。

**CLR-021  有効/無効：**ルールごとに切替可能で、無効時は薄く表示するが順序を変えない。再有効化も元位置で行う。

**CLR-022  削除：**確認ダイアログ後に完全削除し、Undoは提供しない。複製機能も提供しない。

**CLR-023  検証：**入力欄付近にエラーを表示し、1件でもエラーがあれば保存ボタンを無効化する。保存後は一覧へ戻り、内容・優先順位・色を即時反映する。

**CLR-024  キャンセル：**未保存変更がある場合だけ破棄確認を表示し、破棄時は編集内容を捨てる。一時保存・次回復元は行わない。

# 12 エラー処理

**ERR-001  基本原則：**一部の失敗で全予定を空にせず、最後に正常取得できたデータを維持し、正常部分を継続利用する。

**ERR-002  表示単位：**同期成否はアカウント単位で管理し、カレンダー単位の失敗も保持する。1カレンダーでも失敗が残るアカウントはメイン画面で同期エラー扱いとする。

**ERR-003  カレンダー警告：**設定画面の該当カレンダーに警告アイコン/状態を表示し、ホバー等で詳細を確認できる。アカウント警告と併用する。

**ERR-004  部分復旧：**失敗していたカレンダーが正常同期した時点でそのカレンダーだけ警告を解除する。全対象カレンダーが正常になった時点でアカウント警告を解除する。

**ERR-005  認証エラー：**アカウント登録を削除せず認証エラーとして保持し、自動で認証画面を開かない。メイン警告または設定から再認証できる。

**ERR-006  メイン再認証導線：**警告アイコンのホバーでアカウントと原因を示し、クリック後の簡易ポップアップに再認証ボタンを出す。警告クリックだけではブラウザを開かない。

**ERR-007  全OFF例外：**表示ONカレンダーが0件のアカウントは、認証エラーでもメイン警告を出さず、設定画面だけで状態を確認する。ONへ戻したとき必要なら警告と再認証導線を有効化する。

**ERR-008  ネットワーク/API：**前回キャッシュと最終正常更新時刻を表示し、短時間再試行後は通常周期へ戻る。再取得成功時にエラー表示を自動解除する。

**ERR-009  レート制限：**通常通信失敗と区別し、サービス指示に従って再試行する。必要に応じて『レート制限中』を表示する。

**ERR-010  設定破損：**破損ファイルを退避し、初期設定で継続起動する。

**ERR-011  キャッシュ破損：**破損キャッシュを破棄し、空状態から最新同期を開始する。

**ERR-012  異常終了：**次回起動時に『前回正常終了しなかった』等をメイン画面やダイアログへ表示せず、ログに記録し通常の復旧処理を行う。

**ERR-013  通知抑制：**同期エラー、レート制限、予定の終了ではWindows通知、バルーン通知、サウンドを出さず、タスクトレイアイコンもエラー用に変更しない。1.1.0で追加した予定開始前の通知（13.3）だけが例外であり、それ以外の事象では通知を出さない。

**ERR-014  長文表示：**エラー状態がメインステータスに収まらない場合は1行省略し、ツールチップで全文を示す。

# 13 ウィンドウ・タスクトレイ・通知・DPI仕様

## 13.1 メインウィンドウ

**WIN-001  通常ウィンドウ：**常に最前面にせず、通常サイズで自由に移動・リサイズできる。**最大化を許可する（1.2.0で変更。1.1.0までは最大化ボタンを無効化していた）。** 最大化ボタン、タイトルバーのダブルクリック、Win+↑、画面端へのスナップは、いずれもWindowsの通常ウィンドウの挙動に従う。**個別に制限しない。** 変更の理由は、ウィンドウ上端を画面上端までドラッグして高さを画面いっぱいに合わせる操作（垂直方向のスナップ）が要望され、これがWindowsでは最大化可能なウィンドウであることを条件とするためである。**スナップだけを許可することはできない。**

**WIN-001a  最大化状態の非保存（1.2.0で変更）：**最大化した状態は保存せず、次回起動時は通常状態で復元する。最大化中は位置・サイズを保存しない。**スナップした大きさは保存し、真の最大化は保存しない（1.2.0で決定。2026-09-09 実測）。** 判別は`WindowState`で行う。**上下方向最大化と左右半分へのスナップはいずれも`WindowState.Normal`のままである**（`showCmd`が`SW_SHOWNORMAL`、`IsZoomed=False`）。**真の最大化だけが`Maximized`になる。** したがって、位置・サイズの取得は**`Normal`のときは実際のウィンドウ矩形、それ以外は`Window.RestoreBounds`**とする。`RestoreBounds`はWin32の`rcNormalPosition`（最大化・最小化する前の矩形）であり、**`Normal`でもスナップ前の矩形を返す**ため、これだけを使うとスナップした大きさが失われる。

**WIN-002  右端非強制：**画面右端への自動配置、固定、AppBarによる作業領域予約を行わない。他アプリを覆う/覆わない動作は通常ウィンドウのOS挙動に従う。

**WIN-003  最小サイズ：**最小幅・最小高さを設け、情報が読めないサイズへ縮小できないようにする。具体値はUI設計で決める。1.1.0で最小幅を狭めた（値は `docs/technical-design/13-window-tray-single-instance-dpi.md` と `LayoutMetrics` を正とする）。

**WIN-004  位置・サイズ保存：**終了時の位置・サイズとモニタを保存し、次回起動時に復元する。

**WIN-005  復元補正：**保存モニタがあればそのモニタへ復元し、なければプライマリモニタ右端へフォールバックする。画面外なら操作可能範囲へ補正する。

**WIN-006  DPI：**Per-Monitor DPIに対応し、モニタ移動やDPI変更でサイズ、レイアウト、行高さ、時刻欄、フォント、保存状態を再計算する。

**WIN-007  最小化：**最小化ボタンは表示し、タスクバーへ通常最小化する。最小化時は詳細ポップアップを閉じ、復元しても自動再表示しない。

**WIN-008  閉じる：**メイン画面の×では終了せず、ウィンドウと詳細ポップアップを非表示にしてタスクトレイへ常駐する。

**WIN-009  完全終了：**タスクトレイの終了で確認せず終了する。同期をキャンセルし、中途半端な結果を保存せず、設定/ウィンドウ状態を保存する。

**WIN-010  再表示：**タスクバーのアプリアイコン操作は、非表示なら再表示、表示中ならアクティブ化する。新規ウィンドウは生成しない。

**WIN-011  再表示スクロール：**タスクトレイ格納前の一覧スクロール位置を維持する。アプリ終了後の次回起動では復元せず、直近予定から表示する。

## 13.2 タスクトレイ

**WIN-012  メニュー：**『表示/非表示』『今すぐ更新』『設定』『終了』を提供する。

**WIN-013  ダブルクリック：**メインウィンドウを常に表示して前面へ出す。表示中なら前面化し、表示/非表示トグルにはしない。

**WIN-014  非表示中動作：**外部同期、1分内部更新、終了済み除外、進行判定、キャッシュ更新を継続し、再表示時に最新状態を見せる。

**WIN-015  非表示中通知：**同期エラーや予定の終了では通知せず、再表示時のメイン画面状態で確認する。予定開始前の通知（13.3）は、ウィンドウ非表示中も出す（1.1.0で追加）。

**WIN-016  自動起動：**Windows起動時の自動起動を設定でON/OFFでき、初期値はONとする。

**WIN-017  1ユーザー1インスタンス：**同一Windowsユーザーでは1インスタンスだけ許可し、2回目の起動は既存インスタンスを表示・前面化して新プロセスを終了する。

## 13.3 通知

**本節は1.1.0で追加した。** 1.0.0では通知を実装していない。

**NTF-001  対象：**時刻が設定されている予定だけを対象とする。終日予定は対象外とする。開始と終了が同じゼロ時間予定は対象に含める。複数日にまたがる予定は、時刻が設定されていれば開始日時で1回だけ通知する。

**NTF-002  絞り込み：**通知の対象は、一覧に表示される予定と同じ範囲とする。有効なアカウントの表示ONカレンダーだけを対象とし、一覧と判定がずれないようにする。

**NTF-003  判定：**1分ごとの内部更新（FUN-003）と同じ分境界で判定する。通知するのは、通知時刻（開始時刻の指定分前）を過ぎ、かつまだ開始していない予定とする。専用のタイマーは設けない。

**NTF-004  取りこぼし：**開始済みの予定は通知しない。スリープや終了で通知時刻を過ぎた分は捨てる。後追いの通知は出さない。

**NTF-005  重複防止：**同じ予定について通知は1回とする。開始時刻が変更された場合は、開始前であれば再度通知する。通知済みの記録はアプリ実行中だけ保持し、保存しない。

**NTF-006  抑制の初期化：**アプリ起動直後、通知をOFFからONへ変えた直後、通知タイミングを変更した直後は、その時点で通知時刻を過ぎている予定を通知しない。起動や設定変更の直後に通知がまとまって出ることを避ける。

**NTF-007  集約：**同じ判定で複数の予定が該当した場合は1通に集約する。開始が最も早い1件を示し、残りは件数で示す。

**NTF-008  表示方式：**タスクトレイのバルーン通知で表示する。表示位置、見た目、表示時間、サウンドはWindowsに従う。集中モードなどのOS設定で抑制されることがあり、アプリ側では抑制を解除しない。

**NTF-009  操作：**通知のクリックに動作を割り当てない。スヌーズ、通知の履歴、通知からの予定操作は持たない。

**NTF-010  ログ：**通知に関して件名、説明、場所、URLをログへ記録しない（LOG-005）。

# 14 キーボード操作

**KEY-001  Tab順：**Windows標準に近く、視覚的な並びに沿って更新ボタン、設定ボタン（1.1.0で追加）、予定行内の操作可能要素、その他の操作可能UIを巡回する。表示専用ラベルと日付ヘッダーは対象外とする。

**KEY-002  一覧移動：**上下矢印で予定行だけを移動し、日付ヘッダーを飛ばす。画面外へ移動する場合は自動スクロールする。

**KEY-003  予定Enter：**予定行フォーカス中のEnterで詳細ポップアップを表示する。Spaceには動作を割り当てない。

**KEY-004  会議アイコン：**一覧の会議参加アイコンをTabフォーカス対象とし、Enterで会議URLを開く。詳細ポップアップは開かない。

**KEY-005  一覧取得元記号：**一覧のG/M記号はキーボードフォーカス対象にしない。

**KEY-006  詳細元予定操作：**詳細ポップアップ内の元予定を開く操作はTabフォーカス対象とし、Enterで元サービスの予定ページを開く。

**KEY-007  詳細URL：**詳細内の全クリック可能URLを表示順にTabフォーカスでき、Enterで既定ブラウザを開く。

**KEY-008  Esc：**詳細ポップアップを閉じる。テキスト選択中でも同じ動作とし、メイン画面は非表示にしない。

**KEY-009  コピー：**詳細内の選択可能テキストでCtrl+Cを使用できる。

**KEY-010  専用ショートカット：**初期版ではグローバル/専用ショートカットキーを設けない。

**KEY-011  フォーカス維持：**一覧更新後も同一予定IDがあればフォーカスを維持し、削除時は次行優先、次行がなければ前行、空なら解除する。

# 15 ログ仕様

**LOG-001  出力先：**ローカルファイルへ最低限の運用ログを出力する。詳細デバッグログの常時出力やログレベル設定は初期版に含めない。

**LOG-002  ライフサイクル：**アプリ起動・終了、異常終了検知に必要な情報を記録する。

**LOG-003  同期：**サービス/アカウント/カレンダーの同期開始、成功、失敗、取得件数、最終結果を記録する。

**LOG-004  障害：**認証エラー、APIタイムアウト、一時リトライ、レート制限、設定/キャッシュI/Oエラー、想定外例外を記録する。

**LOG-005  予定情報最小化：**件名、説明、場所などの内容は原則記録しない。必要に応じてイベントID、件数、アカウント識別情報、エラーコード、API応答状態だけを記録する。

**LOG-006  ローテーション：**日単位またはサイズ単位でローテーションし、一定世代だけ保持して古いログを自動削除する。最大サイズ・保持日数・世代数は実装設計で決める。

**LOG-007  アクセス：**一般設定からログフォルダと最新ログを開ける。

# 16 非機能要件

**NFR-001  応答性：**同期・ページング・リトライをバックグラウンドで実行し、一覧閲覧と主要操作をブロックしない。

**NFR-002  視覚安定性：**更新で全体空表示、明確なちらつき、スクロールジャンプ、フォーカス消失を可能な限り生じさせない。

**NFR-003  一貫性：**部分成功を活用し、正常なアカウント/カレンダーを失敗側へ巻き戻さない。ファイルは原子的に更新する。

**NFR-004  復旧性：**ネットワーク、API、設定破損、キャッシュ破損、異常終了があっても可能な限り起動を継続し、キャッシュまたは最新同期へ復旧する。

**NFR-005  可読性：**予定色に対して文字・アイコン・進捗のコントラストを自動補正し、ライト/ダークテーマの双方で識別可能にする。

**NFR-006  アクセシビリティ：**基本操作をキーボードで実行でき、フォーカス位置を明示し、OS標準のツールチップ動作とDPIに追従する。

**NFR-007  スケーラビリティ：**表示件数上限を設けずAPIページングを完了する。ただし仮想化等の具体的な大量表示最適化は技術設計で決める。

**NFR-008  API負荷：**アカウント並列数を内部制限し、表示対象がないアカウントを同期せず、レート制限指示へ従う。

**NFR-009  プライバシー：**ログへ予定本文を出さない。ただし初期版の設定/キャッシュは平文であるため、ローカルユーザー権限の範囲外の防御は提供しない。

**NFR-010  保守性：**共通予定モデル、設定/キャッシュのスキーマバージョン、サービス別アダプターにより将来変更へ備える。

**NFR-011  単一実行：**1ユーザー1インスタンスにより設定・キャッシュへの同時書込みを防ぐ。

**NFR-012  OS適合：**Windows標準のテーマ、DPI、ウィンドウ、タスクバー、タスクトレイ、既定ブラウザの挙動へ合わせる。

# 17 データ仕様

内部共通モデルはサービス固有レスポンスを直接UIへ渡さず、次の論理項目を最低限保持する。具体的な型・NULL規則・JSONスキーマは技術設計で確定する。

| 区分 | 主な項目 | 用途 |
| --- | --- | --- |
| identity | eventId, occurrenceId, provider, accountId, calendarId | 更新・フォーカス・詳細の安定識別 |
| content | title, location, description, meetingUrl | 詳細表示用。説明は表示時にプレーン化 |
| time | start, end, sourceTimeZone, allDay | UTC/元TZを保持しWindowsローカルへ変換 |
| span | isMultiDay, displayStartDate, displayEndDate | 終日・日付またぎ表示 |
| status | cancelled, responseStatus | キャンセル除外・参加状態表示 |
| color | sourceEventColor, resolvedColor | ルール適用前後を分離 |
| links | sourceDetailUrl/identifier | 元予定ページを開く |
| calendar | calendarName, calendarColor | 一覧識別・オフライン復元 |

**DAT-001  ID安定性：**同期間で同一予定/同一繰り返し回を識別できるキーを作り、差分更新、フォーカス維持、詳細更新へ使用する。

**DAT-002  時刻保持：**比較・同期用の正規化時刻と元サービスのタイムゾーン情報を保持し、UIではWindowsローカル時刻へ変換する。

**DAT-003  終了境界：**終日イベントの排他的終了日をユーザー認識上の最終日へ変換する。

**DAT-004  色分離：**元サービス色、ユーザールール結果、最終表示色を分離して再評価可能にする。

**DAT-005  スキーマ：**設定とキャッシュに独立したスキーマバージョンを持たせ、将来移行を判定できるようにする。

# 19 矛盾・重複の統合方針

会話中の提案・途中決定・後続変更を比較し、次のように統合した。後から明示された決定を優先し、提案だけでユーザーが選ばなかった内容は仕様へ採用していない。

| 論点 | 途中の差異 | 採用した解消方針 |
| --- | --- | --- |
| 更新周期 | API更新を1分と読める発言と5分初期値 | API再取得は初期5分・固定候補で変更可。表示内部更新だけ1分。 |
| 更新中の手動操作 | 取得中も手動更新可 / 後段でボタン無効 | 後段を優先し、同期中の手動更新ボタンは無効。他UI操作は可能。 |
| 重複更新 | ボタン無効 / 更新要求を1回集約 | ユーザー操作は無効。自動周期や復帰等の内部競合はアカウント単位で1回へ集約。 |
| 終了時キャッシュ | 終了時に最新キャッシュ保存 / 同期成功時だけ保存 | 後段の明示を優先。終了時は再保存・再同期せず、中途結果を破棄。 |
| 正常同期表示 | 『正常』表示 / 正常時は非表示 | 後段を優先し、正常時は同期状態を表示しない。エラー時だけ対象アカウントを示す。 |
| サービス/アカウント状態 | サービス単位表示 / アカウント単位管理 | アカウント単位を正とし、カレンダー失敗も保持。サービス名は取得元識別に使う。 |
| 参加状態 | 全状態表示 / 注意状態のみ | 後段を優先し、承諾済みは通常、辞退・未回答・仮承諾等だけ一覧へ表示。 |
| カレンダー一括操作 | 一括ON/OFF選択後の訂正 | ユーザーの明示訂正を優先し、一括操作は設けない。 |
| 認証情報 | 安全な保存領域の提案 / ローカル設定ファイル選択 | 選択結果を優先し、初期版は平文設定ファイル。将来の安全化だけ対象外候補。 |
| 右端配置 | AppBar等の提案 / 制御不要の明示 | 右端は利用例。通常ウィンドウで自動ドッキング・領域予約・最前面なし。 |
| 詳細の取得元アイコン | サービス名横のアイコンなし / 元予定を開くアイコン保持 | 表示ラベルは文字列のみ。元予定を開く独立操作だけを補足エリアに置く。 |
| 色の優先 | 元サービス色を基本 / 独自ルール上書き | 独自ルール最優先、次に元サービス色、最後に共通デフォルト色。 |
